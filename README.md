# Portfolio Item

How can I ensure that my code, program, or software is functional and secure?
I can start by checking the requirements and testing what the software should do, including what should happen when someone enters invalid information. In Project One, I used JUnit 5 to test the contact service with valid records, duplicate IDs, missing contacts, and incorrect field values. For example, the tests make sure a phone number has exactly 10 digits and that adding a contact with an existing ID throws an exception. I also used separate test setups so one test would not affect another. Across the full project, 39 tests passed and the production classes reached 100% line coverage. That gave me confidence in the basic functions, but I learned that good coverage does not guarantee a program is completely secure. I would still need to review possible security risks and test how the software behaves when connected to other systems.
How do I interpret user needs and incorporate them into a program?
I interpret user needs by breaking the requirements into specific actions and rules that I can build and test. For the contact service, that meant understanding which information could be updated, which values had limits, and why every contact needed a unique ID. I turned those rules into methods for adding, deleting, and updating contacts, then wrote tests to check both successful actions and expected errors. One example is rejecting a duplicate contact ID instead of allowing it to replace an existing record. Working from the requirements helped me focus on what the user actually needs rather than adding features that were never requested.
How do I approach designing software?
I try to keep the design organized by giving each class a clear responsibility. In Project One, the Contact class stores information and validates its fields, while ContactService handles adding, deleting, and updating contact records. Keeping those responsibilities separate made the code easier to understand and helped me test one behavior at a time. I also think about situations that could cause problems, such as missing IDs or invalid updates, instead of designing only for the normal case. After making changes, I use the unit tests to check that existing functions still work. In future projects, I want to improve my testing by checking exact boundary values and getting another perspective on cases I may have missed.
